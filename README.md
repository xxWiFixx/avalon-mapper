# Avalon Mapper

Приложение-компаньон для Albion Online: строит карту Дорог Авалона по тому, что видно
на своём же экране. Наводишь курсор на портал, жмёшь хоткей — приложение читает подсказку
игры («Путь Авалона в …», вместимость, время закрытия), кладёт портал в граф и показывает
над миникартой, что находится в зоне за ним. По накопленному графу ищется маршрут, включая
вариант «выйти в мир, пробежать пешком, зайти обратно».

Работает только на Windows: захват через GDI/BitBlt, проверка процесса игры через tasklist.

## Что приложение делает с вашим компьютером

Приложение просит права администратора, слушает мышь и клавиатуру и снимает экран.
Это ровно тот набор, которым пользуются шпионские программы, поэтому ниже — что именно
происходит и где это проверить в коде. Исходники открыты специально для этого.

| Что | Зачем | Насколько узко | Где смотреть |
| --- | --- | --- | --- |
| Перехват клавиатуры и мыши | поймать одну горячую клавишу поверх окна игры | код клавиши сравнивается с одним сохранённым биндом; ни одно нажатие не пишется ни в файл, ни в журнал, ни в сеть | `app/main.js`, `setupHook` |
| Снимок экрана | прочитать подсказку портала под курсором и полоску с названием зоны | обычно снимается прямоугольник, а не весь экран (см. ниже, когда бывает иначе); на диск кадр попадает, только если включить «Сохранять снимки хоткея» — тогда это ровно два файла с перезаписью | `app/lib/capture-gdi.js`, `saveShots` |
| Права администратора | Albion защищён BattlEye: без них Windows не отдаёт нажатия, пока игра в фокусе | только по явному нажатию кнопки и с подтверждением в диалоге | `restart-as-admin` |
| Буфер обмена | вставить имя зоны в поиск игровой карты | только имя зоны за порталом, только по хоткею, отключается галочкой | `copyWorldZone` |
| Сеть | общие карты и проверка новой версии | наружу уходят только пара зон, размер портала и время закрытия. **Ни позиция игрока, ни его след, ни журнал не выгружаются никогда**; ник не уходит в общую карту | `app/lib/sync.js` |

Чего приложение не делает: не читает память игры, не отправляет нажатия в игру,
не скачивает и не запускает файлы само (новая версия — ссылка в браузер, ставите руками).

### Когда снимается весь экран

В обычной работе — никогда. **Приложение снимает ровно два прямоугольника, и оба маленькие:**

| Когда | Что снимается |
| --- | --- |
| Опрос зоны, раз в 1,5–6 с | полоска **380×30** в правом нижнем углу (4–8 мс) |
| Хоткей | квадрат **1440×700** вокруг курсора |

Оба снимка по хоткею — квадрат у курсора и та же полоска зоны — берутся в одно мгновение
нажатия, до всякого распознавания. Доснять что-то потом, по результату разбора кадра,
нельзя: курсор к этому времени уже уедет.

Ни при свёрнутой игре, ни при нечитаемой плашке приложение больше никуда не заглядывает:
если плашки зоны нет, читать нечего. Не читается три минуты подряд — оно прямо говорит,
что область стоит задать мышью, вместо того чтобы перебирать экран.

**Весь экран снимается только в двух случаях, и оба не про обычную работу:**

| Когда | Почему иначе нельзя |
| --- | --- |
| «Выбрать мышью» область плашки зоны | игрок сам выбирает область и должен видеть, из чего выбирает; один кадр по нажатию кнопки |
| Прямой захват прямоугольника (BitBlt) отвалился | у запасного пути (`desktopCapturer`) прямоугольника нет вовсе — он умеет только экран целиком |

Про второй случай приложение говорит прямо: «быстрый захват отключился, будет заметно
медленнее». Молча тормозить оно не станет.

Раньше весь экран снимался ещё и в фоновом опросе, причём мог повторяться бесконечно —
у игрока со свёрнутой игрой или несовпадающей областью плашки это происходило каждые
1,5–6 секунд. Самая дорогая операция во всём приложении: 520–990 мс на 4К против 4–8 мс
на прямоугольник.

Окна интерфейса не имеют доступа к Node, работают в песочнице, не могут открыть новое
окно или уйти на чужой адрес — см. `SAFE_WEB` и `lockNavigation` в `app/main.js`.

## Запуск

```
cd app
npm install
npm start
```

Хоткей не долетает до приложения, пока в фокусе окно игры, если приложение запущено без прав
администратора: Albion защищён BattlEye и работает с повышенной целостностью. Поэтому в бою
запускать через `app/Avalon Mapper.bat` — он сам поднимает права через UAC.

```
npm test        # роутер, близнецы имён, геометрия плашки, разбор времени, синхронизация
npm run simulate # сквозной прогон 25 калибровочных кадров через боевой распознаватель
```

## Настройки

Приложение снимает экран, поэтому каждый снимок выключается отдельно — в панели
«Настройки» окна карты.

| Переключатель | Что делает, когда выключен |
| --- | --- |
| Плашка поверх игры | по хоткею ничего не всплывает; портал всё равно записывается в карту |
| Карта зоны в плашке | остаются название и активности, блок втрое ниже |
| Следить за плашкой зоны | экран внизу больше не снимается — **приложение не знает, где персонаж**: ни следа, ни автоматических рёбер. Зону можно задать руками через окно поиска (Ctrl+Enter) |
| Снимок области у курсора | по хоткею вместо чтения подсказки открывается окно поиска зоны — те же сокращения, что в поле «Куда» (`couexa` → Coues-Exakrom) |
| Копировать имя зоны мира | имя не-авалонской зоны за порталом не кладётся в буфер обмена |
| Сохранять снимки хоткея | в `%APPDATA%/avalon-mapper/shots` не пишутся два файла (что было у курсора и что было в плашке зоны) |

### Темы

«Настройки» → «Прочее» → «Оформление». **Плашки поверх игры это не касается: она лежит
на игровой картинке и остаётся тёмной всегда** — светлая засветила бы собой пол-экрана
в бою. Тема относится только к окну карты.

| Тема | Какая |
| --- | --- |
| **Авалон** (по умолчанию) | тёмная с фактурой игры: тёмное дерево, кость, золото |
| **Уголь** | тёмная нейтральная в духе интерфейса Claude: тёплый графит и терракота |
| **Пергамент** | светлая: тёплая бумага, коричневые чернила, то же золото |

«Пергамент» — не инверсия тёмной и не серо-белый дашборд: материал тот же (интерфейс
Albion), только берётся не панель тёмного дерева, а пергамент. Холодного серого в ней
нет ни одного.

У «Угля» есть размен, который стоит знать. Акцент в приложении несёт смысл: им горит
канал, куда уходят порталы, и им же подсвечен маршрут. Рядом живут ещё два смысловых
цвета — «портал скоро закроется» и «удалить». Золото «Авалона» разводится с ними легко,
а терракота садится ровно между оранжевым и красным, поэтому в «Угле» **оба соседа
отодвинуты**: «скоро закроется» ушло в янтарь, «удалить» — в откровенно красный. Иначе
на графе маршрут и закрывающийся портал читались бы одним цветом.

Всё оформление висит на переменных CSS (`app/ui/style.css`, блок «ТО, ЧТО МЕНЯЕТ ТЕМА»),
поэтому тема переопределяет 96 имён, а не правит двести мест. Что при этом
переворачивается у «Пергамента» по смыслу, а не по яркости:

| | Тёмная | Светлая |
| --- | --- | --- |
| фаска (`--hi-*`) | белая | **белая же, но сильнее** — свет по-прежнему сверху |
| заливка под наведением (`--wash-*`) | белая | **тёмная**: белое по светлому не видно |
| `--gold-hi` («заметнее») | светлее золота | **темнее золота** |
| `--gold-deep` («тише») | темнее золота | **светлее золота** |
| тень под заголовком | чёрная | **белая**: на светлом букву поднимает высветление |
| тени | чистый чёрный | тонированы в цвет бумаги |

Цвета зон (`--z-*`) не переопределяются ни одной темой: это данные игры, а не оформление.
Меняется только цвет НАДПИСЕЙ на фишках — светлая пастель на светлом фоне нечитаема.

Граф рисуется на canvas и переменных CSS не видит, поэтому `app/ui/graph-style.js` читает
их сам и пересобирается на каждую смену темы. Второго списка цветов не заводится: разъедься
он с `style.css` — граф светил бы костяными подписями по пергаменту.

Посмотреть тему, не открывая настроек: `?theme=coal` или `?theme=light` в адресе стенда
(`node tools/dev-server.js`, затем `http://localhost:5178/ui/index.html?theme=light`).

### Место плашки: вопрос при закрытии

«Задать место» переводит плашку в режим перетаскивания поверх игры, а кнопка «Готово»
остаётся в окне настроек. Закрыть окно, не ответив, — обычное дело: плашку тянут, потом
кликают мимо. Раньше режим при этом **оставался включённым**, а единственный выход
(Enter/Esc по самой плашке) к тому моменту уже забывался.

Теперь закрытие окна посреди режима спрашивает, сохранять ли новое место, — но **только
если место или размер действительно менялись**. Подтверждение на пустом месте это тот же
молчаливый выбор, только с лишним кликом, поэтому без изменений режим просто снимается.
Esc на вопросе значит «вернуть как было» — ровно то же, что Esc по плашке.

Область плашки зоны настраивается там же, в «Настройках»: кнопка «Выбрать мышью» прячет
окно приложения, ждёт, пока Windows уберёт панель задач с низа экрана (пока наше окно
в фокусе, она закрывает как раз плашку), и только потом снимает кадр для обводки.

Размер плашки — ползунок 60…250 %, сколько держать её на экране — ползунок 3…30 секунд,
место — кнопка «Задать место»: плашка становится
кликабельной прямо поверх игры, тянется мышью, колесо меняет размер, Enter сохраняет,
Esc возвращает как было. Геометрия (место, размер, упоры у краёв экрана) считается в
`app/lib/overlay-place.js` и покрыта тестом `app/test/overlay-place.test.js`.

### Строка окна поиска

`couexa 5 36` — имя зоны и, необязательно, время до закрытия портала.
**Одно число — минуты, два числа — часы и минуты**; разделитель любой: пробел, точка,
двоеточие, «ч». Голые цифры всегда минуты (`115` → 115 минут), потому что игра пишет
минуты без ведущего нуля («11 ч 5 м») и правило «две последние цифры — минуты» прочитало
бы `115` как 1:15. Кто хотел час пятнадцать — ставит разделитель: `1.15` или `1 15`.

Под полем строка эха: что понято словами и во сколько портал закроется по часам —
ошибка видна до Enter. Не понятое время блокирует Enter. Размер портала (7 или 20) —
двумя кнопками, а не третьим числом: `couexa 20` невозможно честно развести между
«20 минут» и «портал на 20». Разбор строки — `app/ui/search-line.js`, тест —
`app/test/search-line.test.js`.

## Откуда портал

Ребро «зона → зона» появляется, только если известно, ОТКУДА портал. Раньше правило было
молчаливым: брали последнюю известную зону. Пока плашка читается — честно, но стоит ей
один раз не прочитаться (переход между зонами, экран загрузки, плашку заслонило), и портал
уезжал не туда: игрок прошёл A → B, проверил в B портал в C, а на карте появлялось ребро
**A ⇄ C**, и портала A ⇄ B не существовало вовсе. Ошибка выглядела как нормальная запись.

Теперь решение принимает `app/lib/origin.js`:

| Что известно | Что делаем |
| --- | --- |
| Плашка прочиталась на кадре этого же нажатия | берём её |
| Не прочиталась, но зону подтверждали ≤ 20 с назад | верим ей |
| Не подтверждали дольше | **откладываем портал** и просим внеочередной опрос |
| Слежение за зоной выключено | верим зоне, заданной вручную |

Отложенный портал ждёт до 25 секунд (обычно 1–3), ложится в карту, как только плашка
прочиталась, и всё это время виден в плашке строкой «жду, откуда портал». Не дождался —
приложение говорит об этом вслух, а не пишет наугад. Правило покрыто тестом
`app/test/origin.test.js`.

### Ждём исходники

Две карты нельзя починить обрезкой — брак в самом скачанном ассете:
`Feritos-Enomaum` (поверх карты нарисован игровой круг выделения) и `Tebitos-Odoxlum`

`app/assets/avalon-maps/` под теми же именами и прогнать
`node tools/crop-maps.js && node tools/check-crops.js && node tools/build-crops-page.js`.

## Общие карты

Найденный портал попадает туда, где включены тумблеры в настройках (шестерёнка рядом
с ником → «Куда сохранять портал»). Тумблеры независимы: можно во все места сразу,
можно ни в одно. Список каналов слева отвечает на другой вопрос — что ПОКАЗАТЬ на графе;
рядом с каналом горит точка, если новые порталы уходят и туда.

| Тумблер | Куда уходит |
| --- | --- |
| В свою карту | `map.json` в `%APPDATA%/avalon-mapper` — файл на этом компьютере, наружу не уходит |
| В общую карту | одна карта на всех, id постоянный |
| В карту «…» | комната друзей; её код (uuid) создаёт один из вас и присылает остальным |

Комнат может быть сколько угодно. Создать свою или войти по чужому коду — кнопка «+»
над списком каналов. Всё общее (комнаты и общая карта) требует входа через Discord;
личная карта работает и без входа.

### Роли в картах друзей

Код карты и есть приглашение: кто его знает, тот войдёт. Для двоих друзей этого хватает,
для гильдии — нет, поэтому у каждого участника есть роль. **Новичок входит наблюдателем**
и ничего не пишет, пока хранитель не переведёт его выше. Правая кнопка по значку карты →
«Настройки ролей»; ник переносится между графами мышью.

| Роль | Что может |
| --- | --- |
| Наблюдатель | только смотрит карту |
| Разведчик | добавляет порталы; при включённом пороге они ждут подтверждений |
| Проверенный | добавляет без подтверждений |
| Хранитель | всё выше, плюс удаление порталов, роли и порог |

Хранителей назначает и снимает только владелец карты — иначе первый же назначенный
хранитель мог бы назначить второго, и карта ушла бы из рук без единого злого умысла.

Порог подтверждений включается тумблером «Проверенные участники» и задаётся числом.
Пока порога нет, разведчик и проверенный делают одно и то же, поэтому графа «Проверенный»
без порога и не показывается.

### Что попадает в общую карту

Порог общей карты — **3**, и подтверждения считаются весом, а не штуками: портал,
прочитанный с экрана, весит единицу, вписанный руками — половину. То есть либо три
снимка, либо шесть ручных записей от разных аккаунтов.

**Портал без времени закрытия в общую карту не уходит вовсе** — ни клиент его туда не
поставит в очередь, ни сервер не примет. Время — половина смысла портала: без него ребро
живёт двенадцать часов «на всякий случай», и чужой маршрут повёл бы к закрытому проходу.
В своей карте и у друзей такие порталы остаются: там знают, кто их записал.

Что уходит: пара зон, размер портала, время закрытия, откуда знание (`ocr` — прочитан
тултип, `manual` — зона выбрана в окне поиска) и ник. **Ник не передаётся в общую карту** — ни клиентом, ни функцией `push_edges`: связка
«кто где был» из неё выводиться не должна. Позиции игрока, след и журнал не выгружаются
никогда и никуда.

### Что приложение знает о твоём Discord

**Пароль оно не видит и увидеть не может.** Страницу входа открывает системный браузер,
пароль вводится на стороне Discord, назад приходит только код авторизации — а он без
секрета PKCE (тот не покидает твою машину) ничего не стоит.

У Discord запрашивается **только `identify`**: имя, id и аватарка. Почту не просим вовсе —
приложению она не нужна ни для чего, а чего нет, то не утечёт.

На диске (`%APPDATA%/avalon-mapper/auth.json`) лежат токен продления, id аккаунта и ник.
Токен зашифрован средством системы (DPAPI, ключ привязан к учётной записи Windows):
файл, унесённый на другую машину, бесполезен. От программы, работающей под твоей же
учёткой, это не спасает — такой защиты не существует, — но от копирования файла спасает.
Украденный токен в любом случае даёт доступ только к картам порталов, не к аккаунту Discord.

Другие игроки видят твой ник в тех картах, где вы вместе, и больше ничего: ни почты,
ни аватарки, ни id Discord. В общей карте ников нет вовсе.

Чужие рёбра доливаются в свою карту, а не замещают её: размер портала липкий (кто прочитал,
тот и прав), время закрытия берётся более позднее, а своё ребро не понижается до чужого.
Маршрутизатор после этого считает по общему знанию — в этом и смысл.

**В карту попадают только прочитанные порталы.** Приложение не выводит проходы из
перемещений игрока: «был в A, теперь в B — значит между ними портал» верно, только если
ни одной зоны между ними не пропущено, а пропустить их легко (свёрнутая игра, экран
загрузки, смерть с воскрешением, выход из Туманов). Такие рёбра раньше были и рисовались
пунктиром; они убраны, а записанные прежними сборками удаляются при первом же запуске.

Сеть игру не ждёт: портал ложится в очередь на диске (`sync-outbox.json`) и уходит фоном,
раз в 3 с. Нет интернета — полежит и уйдёт потом, очередь переживает перезапуск. Отказ 4xx
не крутится вечно: порция выбрасывается, причина видна в строке состояния под тумблерами.

### Как поднять

Сервер уже настроен: адрес проекта и публичный ключ зашиты в сборку, игроку вписывать
нечего — поля для них из окна убраны совсем. Достаточно войти через Discord, нажать «+»
над списком каналов, создать карту и разослать её код друзьям.

Своё место для карт (если нужно): создать проект в [supabase.com](https://supabase.com)
(бесплатного тарифа хватает), прогнать в SQL Editor `supabase/schema.sql`, затем
`supabase/migration-01-*.sql` и далее по порядку, завести провайдер Discord в
Authentication → Providers и пересобрать приложение со своими `BUILTIN_URL` и
`BUILTIN_KEY` в `app/main.js`.

Публикуемый ключ лежит у каждого игрока — секретом он не является. Таблицы закрыты
через RLS без единой политики, наружу торчат только функции `security definer`, и каждая
из них проверяет вошедшего: без токена Discord не пройдёт ни запись, ни чтение общего.
Право удалять чужие порталы есть у владельца карты и у доверенных, а портал новичка
появляется в общей карте только после трёх подтверждений от разных людей.

## Сборка и раздача

```bash
cd app && npm run dist
```

На выходе `dist/AvalonMapper-<версия>-setup.exe` — обычный установщик Windows (118 МБ),
ставится в профиль пользователя, **прав администратора для установки не требует**. Права
нужны только приложению во время работы (иначе хоткей не долетает поверх Albion) — для
этого в панели есть кнопка «Перезапустить от администратора», и в собранной версии она
поднимает сам exe через UAC, а не .bat.

Что НЕ едет в сборку: исходники карт (29 МБ), атлас иконок, тесты и страницы проверки —
они нужны только инструментам. Словари OCR кладутся рядом с архивом, а не внутрь него:
tesseract открывает их как обычные файлы.

Нативные модули (`sharp`, `koffi`, `uiohook-napi`) собраны на N-API и одинаково годятся
для Node и Electron, поэтому пересборка выключена (`npmRebuild: false`) — иначе на каждой
машине понадобился бы Visual Studio.

### Обновления

Приложение раздаётся файлом, поэтому само проверяет, не вышла ли новая версия: раз в час
смотрит последний выпуск и, если версия там больше, показывает внизу панели плашку
«Вышла версия X» с кнопкой. **Скачивает и ставит человек сам** — ничего
не качается и не запускается автоматически.

Проще всего через **GitHub Releases**: в поле «Где искать новые версии» вписывается
`owner/repo` (или ссылка на репозиторий), дальше приложение само читает последний выпуск
через `api.github.com`, берёт версию из тега и ведёт на страницу выпуска. Ничего
выкладывать вручную не надо — достаточно создать выпуск и приложить к нему установщик.

Второй вариант — свой файл `{ "version": "…", "url": "…", "notes": "…" }` по любому
https-адресу; собрать его вместе с установщиком умеет `tools/release.js`.

В обоих случаях ссылка на скачивание обязана вести **на тот же хост или его поддомен**,
откуда пришёл ответ: `api.github.com` и `github.com` считаются одним, а вот `evil.github.io`
при ответе с `alice.github.io` — уже нет, хотя хвост имени у них общий. Иначе подменённый
ответ увёл бы игрока куда угодно. Само приложение ничего не качает и не запускает:
открывает страницу в браузере, дальше человек ставит руками.

## Данные

`app/data-static/zone-data.json` собирается из двух источников — `tools/build-zone-data.js`:

* сундуки (зелёные/синие/золотые, малые и большие), портал в Бресилиен и фракции
  подземелий — из открытого набора проекта roadinator-web;
* подземелья (соло/групповые/золотые) и ресурсы с размерами — из официального дампа
  игры `world-raw.json` (ao-bin-dumps).

Иконки, которых нет у источника, добирает `tools/make-icons.js`; карты зон обрезаются
«по краям ромба» в `tools/crop-maps.js`. Сверить данные с игрой глазами:
`node tools/verify-sheet.js 50` — листы «карта зоны + что мы про неё думаем».

## Записываемое состояние

Конфиг, карта и снимки хоткея лежат в `userData` (`%APPDATA%/avalon-mapper`), а не в
каталоге программы: после упаковки писать туда нельзя. При первом запуске старые
`app/data/config.json` и `map.json` переносятся автоматически.

Снимков в папке `shots` всегда не больше двух, и каждое нажатие хоткея их перезаписывает:
`1-у-курсора.png` и `2-плашка-зоны.png`. Если какой-то снимок выключен настройкой,
его файл удаляется — чтобы в папке не лежал старый кадр, выдающий себя за свежий.
