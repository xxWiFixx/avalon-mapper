# Разработка и данные

## Сборка

Windows x64, Node.js и npm. Зависимости зафиксированы в `app/package-lock.json`.

```text
cd app
npm ci
npm test
npm run pack
npm run dist
```

`pack` создаёт распакованное приложение, `dist` — установщик NSIS. Настройки сборки находятся в `app/package.json`. Словари `rus.traineddata` и `eng.traineddata` включаются как внешние ресурсы. Тесты, диагностические страницы и исходные изображения карт в установщик не входят.

Для проверки интерфейса: `node tools/dev-server.js`, затем `http://localhost:5178/ui/index.html`.

## Сервер совместных карт

Сервер работает на Supabase. Для отдельного развёртывания:

1. Применить `supabase/schema.sql`, затем миграции по номеру.
2. Включить Anonymous Sign-Ins и настроить Discord в Authentication → Providers.
3. Задать `BUILTIN_SYNC.url` и `BUILTIN_SYNC.key` в `app/main.js` и пересобрать приложение.

Права проверяются серверными функциями. Для облачной карты без Discord создаётся гостевой аккаунт, привязанный к токену этого устройства. Вход через Discord использует OAuth с областью `identify`; при входе активные локальные порталы копируются в карту Discord. Гостевые аккаунты не могут создавать карты друзей или вступать в них. Токены на Windows хранятся через системное шифрование. `migration-10-personal-cloud-and-all-maps.sql` создаёт личные облачные карты и «Все карты»; `migration-11-guest-and-timed-portals.sql` ограничивает гостевые аккаунты и запрещает порталы без времени. Бесплатные аккаунты публикуют порталы по умолчанию; аккаунт с `profiles.plan = 'pro'` может отказаться от публикации и читать объединённую карту. Аккаунт владельца имеет постоянный Pro-доступ. Оплату и выдачу Pro приложение пока не автоматизирует.

Синхронизация передаёт зоны, параметры портала, источник и автора записи. Неотправленные изменения хранятся в `sync-outbox.json`.

`migration-08-shared-map-sync.sql` добавляет версии карт: клиент получает полный состав при изменениях, включая удаления и новые права. Без изменений сервер возвращает только версию и права. Старый `pull_edges` сохранён для совместимости. Отключение отправки и роль наблюдателя не отключают получение карты.

## Проверка совместных карт

`cd app` → `npm run test:shared`. Проверки запускают схемы и миграции в PostgreSQL через PGlite и используют отдельные клиенты с независимыми локальными картами и очередями. Проверяются обмен, подтверждения, таймеры, удаление, права, обрыв связи, перезапуск и обновление сервера. Живой проект Supabase не используется.

Для проверки интерфейса после установки зависимостей запустить из корня `node tools/shared-map-preview.js`, затем открыть:

- `http://127.0.0.1:5189/ui/index.html?client=alice` — владелец.
- `http://127.0.0.1:5189/ui/index.html?client=bob` — наблюдатель.

Стенд использует временную базу и тестовые аккаунты. Добавить тестовый портал можно запросом `POST /test-action?client=alice&action=add`, выдать второму участнику право записи — `action=promote`, уточнить таймер до двух минут — `client=bob&action=correct`. Отправка у второго участника включается в настройках карты.

Для проверки рабочего сервера после миграции предназначен `tools/shared-map-live-check.sql`: он выполняет сценарии с тестовыми пользователями в транзакции и завершает её откатом. Запускать отдельно от миграции, в SQL Editor проекта.

## Данные и ресурсы

Справочник зон собирается `tools/build-zone-data.js` из данных roadinator-web и ao-bin-dumps. Основной и дополнительный ресурсы представлены в `resNodes`. Изображения предметов загружаются с сервера Albion Online.

Условия использования карт мира: [OpenRadar](../app/assets/world-maps-iso/LICENSE-OpenRadar.txt). Файлы лицензий ресурсов сохраняются в `app/assets/`.

Для `Feritos-Enomaum` и `Tebitos-Odoxlum` требуется замена исходных изображений карт: на первом присутствует маркер выделения, второе обрезано.

## Выпуски

Версия задаётся в `app/package.json` и lock-файле. Установщик публикуется в GitHub Releases. Приложение проверяет обновления и открывает страницу выпуска; загрузка и установка выполняются вручную.

Для новых выпусков используется процесс **Verified Windows build** в GitHub Actions. Он создаёт установщик, SHA-256, список зависимостей и подтверждение происхождения. Перед публикацией проверить успешное завершение обоих заданий и перенести файлы из результата этого запуска без повторной сборки. [Проверка установщика](verify-download.md).
